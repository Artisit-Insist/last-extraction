# 0.6 역할별 복장 검증

상용 대작 수준이나 1시간 캠페인의 최종 완성 검증은 아니다. 0.6은 인물의 역할을 구분하는 개발 단계다.

## 변경

경비병은 군복과 철모, 정찰병은 정찰모와 가벼운 장구류, 중무장병은 방탄복을 입는다. 구출 대상은 티셔츠·청바지 또는 작업복을 입는다. 구출 대상을 무장 동료로 전환할 때 복장 표식을 복사하고 저장 복원 시 임무에 맞는 복장을 다시 적용한다. 마지막 헬기 탑승 장면에도 두 종류의 구출 대상 복장이 등장한다.

기존 52개 관절을 유지했다. 얼굴 모델을 새로 다섯 종류 만든 것은 아니다. 새 옷의 정점 웨이트는 기존 인체의 웨이트를 보간하여 연결했으며, 옷 아래 몸은 의상 원본의 가림 영역에 맞춰 숨겼다. 이전 캐릭터·애니메이션·원본은 보존했다.

## 원본과 재제작

- ArtSource/Production/Characters06/CharacterRoles06.blend: 편집 가능한 다섯 복장.
- Characters06/manifest.json, materials.json: 메시와 재질 기록.
- Tools/Character/build_role_variants.py, import_role_variants.py: Blender 제작 / Unreal 변환.
- Game/Production/Rigged/Characters06: 기존 스켈레톤에 연결한 게임 메시.

## 확인

- 각 복장 메시의 모든 정점에 정규화된 관절 웨이트가 있다.
- 5개 복장 × 5개 동작 × 시작·중간·끝, 총 75개 포즈를 평가해 비정상 수치, 2.5m 이상의 급격한 메시 늘어짐, 15cm를 넘는 지면 아래 침범이 없는지 검사했다. 이 수치 검사는 모든 자세가 자연스럽다는 보장은 아니며, 실제 확대 화면도 별도로 확인했다.
- Unreal에서 다섯 메시 모두 기존 CommandoRigged_Skeleton 연결을 확인했다.
- 일반 걷기와 무장 대기, 비무장 대기의 실제 엔진 화면을 확인했다. 왼손은 기존 총 앞 덮개 지지 자세를 유지한다.
- 작업복 색상 이미지가 노멀맵으로 자동 인식된 문제를 발견했다. 텍스처 역할에 따라 압축 형식을 명시하고, 수정된 청색 데님을 실제 화면에서 확인했다.
- Mac arm64 패키징과 strict/deep 코드 서명 검사를 통과했다.

- 패키징된 앱에서 6개 지역 / 42개 임무 / 12명 호송·무장 / 엔딩 13명 탑승을 통과했다. 구출 전후 동일 메시 확인 12/12, 노동자 4명과 민간인 8명이 무장 후에도 같은 복장을 유지했다.
- 자동 진행 시간 1,232.0초, 사망 0회, 적 419명 제압, 지원 사격 280회 이상. 사람의 플레이 시간 또는 전체 캠페인 실시간 FPS 측정 결과가 아니다.
- 경로 시작 오류 0, 이동 충돌 경고 0, 교량 개방 중 경로 재시도 1, VSM 넘침 경고 0.
- 실제 사용자 Campaign.json 두 파일의 SHA-256이 검사 전후 일치했다. 검사는 별도 CampaignTest.json을 사용했다.

원시 결과는 CHARACTERS_06_RESULTS.json 및 전달 폴더 검증결과.md에 기록했다.

## 남은 제한

인체와 얼굴은 여전히 공통 기반이다. 쓰러질 때 총을 놓는 표현, 사망 자세, 활 전용 동작, 더 정교한 얼굴과 의복 디테일은 후속 작업이다. 최적 경로를 아는 자동 검사 시간을 사람의 1시간 플레이 증거로 사용하지 않는다.
