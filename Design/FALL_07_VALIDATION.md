# 0.7 쓰러짐과 무기 낙하

0.7은 개발 단계다. 상용 대작 수준과 약 1시간 캠페인이라는 최종 목표가 완료되었다는 뜻은 아니다.

피격 방향을 인물의 시선 방향과 비교해 앞·뒤·좌·우 쓰러짐을 선택한다. 기존 52개 관절 위에서 무릎, 허리, 팔, 손가락이 풀리는 동작을 직접 만들었다. 모션 캡처 영상에서 가져온 동작은 아니다. 기존 이동·사격·장전 및 총 앞 덮개를 받치는 왼손 자세를 유지한다.

손가락이 열리는 시점에 손의 총을 숨기고, 같은 위치와 방향에 별도의 물리 총을 만든다. 원래 장착된 무기 자료는 보존하고 낙하용 메시만 다섯 충돌 덩어리로 구성했다. 총은 바닥과 충돌하며 플레이어, 사격 판정 및 이동 경로를 막지 않는다. 시체와 무기는 8초 뒤 정리한다. 활을 선택한 주인공의 숨겨진 총은 떨어뜨리지 않는다.

Unreal의 물리 몸체가 한 프레임 늦게 준비되어 최초 속도가 사라지는 문제를 확인했다. 물리 몸체 준비 후 한 번만 낙하 속도를 적용하도록 수정했다. 무거운 조끼, 정찰모, 작업복의 두께 차이는 해당 동작의 바닥 접촉 높이를 별도 보정했다.

## 확인한 범위

- 편집기 게임 실행에서 5개 인물과 4개 방향의 낙하 확인. 최초 검사는 총의 중력 낙하만 됐으며, 수정 후 수평 이동과 회전 속도까지 적용됨을 시간별 위치·속도 기록으로 확인했다.
- 낙하 6초 시점에서 총의 물리 상태 활성화, 속도 0, 원래 손의 총 숨김을 확인했다. 바닥 침범은 넓은 경계 상자의 빈 모서리가 아닌 실제 충돌 덩어리의 정점으로 측정했다.
- 5개 복장 × 4개 방향 × 55프레임 = 1,100개 포즈에서 유한한 정점 좌표, 2.5m 미만의 전체 크기, 바닥 4mm 아래를 넘지 않는 자세를 확인했다. 수치 검사만으로 모든 동작이 자연스럽다고 판정하지 않는다.
- 실제 게임 엔진의 540프레임을 사용한 무음 검토 영상: 전달 폴더의 쓰러짐과_무기낙하_실제화면.mp4. 1280×720, 30fps, 18초. 경비병의 뒤쪽, 중무장병의 오른쪽, 무장 동료의 왼쪽 쓰러짐 순서다. 일반 전투 녹화가 아닌 동작 검토 장면이다.

## 편집 자료

ArtSource/Production/Animation07/FallMotions07.blend와 7개 FBX, fall_manifest.json을 포함한다. Tools/Character/build_fall_motion.py는 제작, import_fall_motion.py는 Unreal 변환, validate_fall_motion.py는 포즈 검사를 수행한다. 원본 동작과 캐릭터를 덮어쓰지 않는다.

## 제한

인물 시체는 관절 물리 인형이 아닌 제작한 동작을 사용한다. 무기만 물리 시뮬레이션한다. 급한 경사나 바위에 맞춰 시체 관절이 개별적으로 적응하는 처리, 활 전용 동작, 더 풍부한 전투 판단과 캠페인 분량은 후속 작업이다.

## 패키징 앱 전체 진행 검사

Mac arm64 앱 빌드와 strict/deep 서명 검사 통과. 6개 지역·42개 임무, 12명 호송과 무장, 엔딩 13명 탑승을 확인했다. 구출 전후 복장 일치 12/12. 적 419명 제압, 사망 0회, 물리 무기 낙하 로그 400개 이상. 실제 사용자 저장 두 파일의 SHA-256은 검사 전후 일치했다.

자동 진행 시간 1232.0초, 검사 벽시계 시간 430.88초. 사람의 1시간 플레이나 실시간 FPS를 증명하는 결과가 아니다. 경로 시작 오류 0, 이동 충돌 경고 0, 교량 개방 중 경로 재시도 1회.

이번 Mac UI 재검사는 잠금 화면 때문에 수행하지 않았다. 엔진 렌더 화면과 패키징된 앱의 전체 진행은 별도로 검사했다.
